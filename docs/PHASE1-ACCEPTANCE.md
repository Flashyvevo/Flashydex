# FlashyDex — Phase 1 acceptance gate (Stage A3)

Current owner gate includes separate user/catalog DBs, versioned zstd pack build/install/cancel/crash/hash/bundle/metrics and .fdx backup/restore. [COMPRESSION-STORAGE](COMPRESSION-STORAGE.md) and BRIEF OWNER UPDATEs govern. [CATALOG-PACKS](CATALOG-PACKS.md) specifies the protocol/evidence; ADR-040–048 supersede A2 single-DB/snapshot-later/raw-backup assumptions. Nothing is marked passed by documentation.

These are requirements to prove, not claims that implementation/tests already pass. BRIEF's Phase 1 scope replaces the scanner-centric full MVP gate for this delivery. Every mutation must have success, validation/failure and rollback/unchanged-data tests. A test uses a fresh temporary SQLite FILE with foreign_keys=ON, not a mock repository or only :memory:. Tests may use explicitly synthetic fixtures; production UI must not contain fake cards, prices or placeholders presented as real data. No live third-party network in repeatable CI tests; keep the verified TCGdex sample shape as a fixture. A separate optional live smoke may inspect a real card.

Test labels: V=vitest (core real temporary SQLite file through SAME sqlite-proxy with Node-test-only better-sqlite3; UI Testing Library), P=Playwright web at 390×844 and 1280×800, M=physical phone/browser or native iOS check explicitly named. Repositories/services are tested directly, NOT HTTP handlers. Native bridge/share/VoiceOver/App Store checks require Mac/device evidence; web/Node passing alone is insufficient. Capture commands/results in implementation reports; no item is passed by writing this document. Cross-contract names follow [API](API.md), [DATA-MODEL](DATA-MODEL.md), [ARCHITECTURE](ARCHITECTURE.md), [IMPORT-EXPORT](IMPORT-EXPORT.md).
