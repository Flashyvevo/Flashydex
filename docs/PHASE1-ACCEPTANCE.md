# Phase 1 acceptance gate

These are requirements to prove, not claims that implementation/tests already pass. BRIEF's Phase 1 scope replaces the scanner-centric full MVP gate for this delivery. Every mutation must have success, validation/failure and rollback/unchanged-data tests. A test uses a fresh temporary SQLite FILE with foreign_keys=ON, not a mock repository or only :memory:. Tests may use explicitly synthetic fixtures; production UI must not contain fake cards, prices or placeholders presented as real data. No live third-party network in repeatable CI tests; keep the verified TCGdex sample shape as a fixture. A separate optional live smoke may inspect a real card.

Test labels: V=vitest unit/integration; P=Playwright at 390x844 unless specified; M=manual physical phone on same private LAN. Each ID requires its named type(s). Capture command/result evidence in implementation reports; a build alone does not prove any criterion. Test suites must be discoverable under paths in ARCHITECTURE.
