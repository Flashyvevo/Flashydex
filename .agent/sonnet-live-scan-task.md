## Build
1. **`lib/recognition/camera.ts`**: `openRearCamera()` → `getUserMedia({ video: { facingMode: { ideal: 'environment' }, width: { ideal: 1920 }, height: { ideal: 1080 } }, audio: false })`. Returns `{ stream, stop() }`. Classify failures: `denied` (NotAllowedError), `unavailable` (NotFoundError/OverconstrainedError/no mediaDevices/insecure), `blank` (stream delivered but `video.readyState < 2` or `videoWidth === 0` after 2.5 s, or track `ended`/`muted` for > 1 s — the iOS standalone bug). Any of these ⇒ the UI falls back to the file-input Take Photo flow **silently** (no error screen; a one-line muted hint "Using the camera app" is fine). Also fall back if the track ends mid-session (permission revoked) — if the user was mid-analysis keep the result.
2. **`lib/recognition/frame-quality.ts`**: pure functions over an `ImageData` sample (downscaled ≤ 320 px): `sharpness` (variance of Laplacian on luma), `glareFraction` (share of pixels with luma > 245 in the central 70 % region), `brightness` (mean luma). Thresholds exported as constants: `MIN_SHARPNESS`, `MAX_GLARE` (e.g. 0.06), `MIN_BRIGHTNESS`. Unit tests with synthetic ImageData (flat → not sharp; checker → sharp; white blob → glare).
3. **`components/scanner/live-view.tsx`**: full-width `<video playsInline muted autoPlay>` with a 63:88 card guide overlay (rounded, lime corners, dimmed outside), status chip ("Hold steady", "Too dark", "Glare — tilt the card", "Blurry — hold still"), a manual shutter button (44 px+, `data-testid="live-shutter"`), and secondary links: Take Photo (system camera), Choose Photo, Search Manually, Browse by Set. Sampling loop via `requestAnimationFrame` throttled to ~6 fps drawing the guide region to an offscreen/DOM canvas (reuse `prepare.ts` encode path for the upload: crop to the guide rect, longest edge 1600, JPEG q0.85). **Auto-capture**: when 4 consecutive samples pass all quality thresholds → capture + submit. Never auto-capture while a request is in flight. Pause sampling (`video.pause()`, stop RAF) when `document.hidden`, resume on visible; stop tracks on unmount/route leave.
4. **Retry policy (`data/recognition.ts`)**: per "scan session" (reset on Scan Another / leaving the route): on `no_match`/`no_card` from a live frame, do NOT show the no-match screen; keep the viewfinder live, show chip "Didn't catch it — trying again", and allow up to **3 attempts within 10 s** (each needs fresh quality-passing frames, min 1.5 s apart, respecting the 30/min server limit — never more than 3 attempts per 10 s). Network/5xx/429 failures count as errors, not attempts, and show the existing error copy. After 3 failed attempts → **coach** state.
5. **`components/scanner/coach.tsx`** (`data-testid="scan-coach"`): "Let's get a cleaner shot" — bullets: "Place the card on a dark, matte surface", "Fill the frame, card flat", "Tilt away from lights or windows to kill glare", "Wipe the sleeve or take it out". Buttons: **Keep Scanning** (resets attempts, back to live), **Take Photo** (system camera), **Search Manually**, **Browse by Set**. If glare was the dominant rejected-quality reason during the session, lead with the glare line; if "Too dark", lead with lighting. File-input mode: after 2 consecutive no-match photos the same coach appears.
6. **`/scan` route**: on mount try the live camera (only if `navigator.mediaDevices?.getUserMedia`); while opening show a skeleton (≤ 2.5 s) — not a spinner that blocks the four buttons. Fallback keeps today's layout exactly. Playwright can force modes via `?camera=live|file` query (dev/test only) and a `window.__fdxFakeCamera` hook that supplies a canvas-captured MediaStream (`canvas.captureStream()`) drawing a given fixture image — use it to test auto-capture, glare rejection (draw a white blob), blur (draw blurred), the 3-attempt → coach path (mock `/api/identify` no_match ×3), fallback-on-blank (stream with 0×0), and permission denied.
7. **Copy** lives in `copy.ts`. Match/candidates/confirm/add/Scan Another unchanged; **Scan Another returns to the live viewfinder** (or system camera in file mode).
8. **Docs**: `docs/UX.md` scanner section: modes, state machine, thresholds, retry policy, iOS standalone caveat with the two bug ids, what is `[needs owner iPhone]`.
